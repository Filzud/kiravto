## 19:36–19:47 — разведка источника (внешний MCP: Playwright)
Ход разведки — по шагам, которые потом оформлены в скилл `source-recon`:

   Запрос к API из `curl` с новой сессией: `{"action_kind":"NEED_AUTH", ...}`. Вывод: простой HTTP-клиент
   не годится.
2. **Playwright MCP** `browser_navigate` на страницу салона — открылась нормально, «428 предложений».
   `browser_network_requests` — встроенного JSON-состояния нет, есть только `sendUserChoice`.
3. Попробовали `POST /-/ajax/desktop-search/listing/` с `dealer_code` — ответ 200, но **651 291 машина**:
   параметр `dealer_code` молча игнорируется. **Ошибка агента, пойманная сразу**: агент сначала посчитал
   эндпоинт найденным; проверка `pagination.total_offers_count` показала, что фильтр не применился.
4. Перехват запросов при клике «стр. 2» (`browser_run_code_unsafe` + `page.on('request')`) показал реальное
   тело: `dealer_id: "20866489"`. С ним — 428, совпадает с сайтом.
5. Сравнение счётчиков с фильтрами и без: `has_image=false` даёт +25 машин (186 новых + 267 с пробегом = 453).
6. Карточка: перебор имён эндпоинтов → `getOfferCard`. Скрипт с параметром `offerID` получал
   `HTTP method not allowed` — **вторая пойманная ошибка**: в удачном вызове через MCP был ещё `offer_id`;
   изоляция по одному параметру показала, что нужен именно `offer_id` в формате `id-hash`.
   Несуществующий ID → `OFFER_NOT_FOUND` (это и стало признаком «снято»).
7. Проверено, что headless Chromium из Python получает тот же JSON (Playwright 1.64 из pip требовал новый
   браузер — откатили на 1.58, под установленный Chromium).
