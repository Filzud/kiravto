# Киравто: склад автосалона → сообщество в Telegram

Сервис сам следит за складом салона **РОЛЬФ Ясенево** на Авто.ру
(`auto.ru/diler/cars/all/rolf_yasenevo_moskva/`), хранит историю цен и статусов, готовит посты
в Telegram (в канал уходит только после кнопки человека), отдаёт данные по HTTP API и через MCP-сервер.

Салон: основной, **РОЛЬФ Ясенево** (`DEALER_CODE=rolf_yasenevo_moskva`, `DEALER_ID=20866489`). На 21.10.2026
в нём больше 100 машин, поэтому запасной салон не понадобился.

**Запасной салон FRESH Москва** разведан агентом (скилл `source-recon`, 8 запросов): `DEALER_ID=23884202`,
676 машин, все с пробегом, скрытых фильтрами нет, те же эндпоинты и формат. Сборщик подходит без правок кода.
Переключение: `DEALER_CODE=fresh_x_syndicate_moskva`, `DEALER_ID=23884202` и **отдельный `DB_PATH`**.
База привязывается к салону при первом прогоне; с другим салоном сервис откажется работать,
иначе первый же прогон «снял» бы весь прежний склад. Указывать нужно оба значения:
`dealer_code` без `dealer_id` источник молча игнорирует и отдаёт всю базу Авто.ру.

## Архитектура

```
 Авто.ру ──(Chromium, своя сессия, fetch к /-/ajax/…)──► source/autoru.py ─► source/parse.py
                                                                              │ (падает громко при смене формата)
                                                                              ▼
 расписание 30–60 мин ─► collector.py ── история, снято/вернулось/перевыставлено/продано, дубли, аномалии
                              │                                     │
                              ▼                                     ▼
                         SQLite data/kiravto.db  ◄─── llm.py (факты из описания с проверкой цитат, кэш, бюджет)
                              ▲  ▲  ▲
   после полного прогона ─────┘  │  └── second_source.py ◄── apiweb.rolf.ru (сайт салона, полный VIN), раз в 6 ч
   market.py ◄── Авто.ру,        │
   похожие у других продавцов    └───── gsheets.py ──► Google Таблица (сервисный аккаунт), раз в 3 ч
          ┌──────────────┬────────┴───────┬────────────────┬───────────────┐
          ▼              ▼                ▼                ▼               ▼
     posts.py      telegram_bot.py     api.py         mcp_server.py     report.py
  (очередь, тексты, (модерация кнопками, (FastAPI,       (8 чтений +      (HTML после
   строка «рынок»)   /status, голос →   токен)          propose_post)    каждого прогона)
                     voice.py → MCP)
```

Задания со звёздочкой (подробно — раздел ниже): `market.py` (ниже рынка), `second_source.py` (сайт салона
rolf.ru), `voice.py` (голосовой вопрос в админ-чате → инструмент MCP), `gsheets.py` (Google Таблица),
`deploy/` (VPS). Всё, что ходит в сеть, делается после прогона склада и записывается в `side_runs`
(запросы, результат); ошибка любого из них прогон склада не портит.

- `kiravto/queries.py` — общий слой чтения: API, MCP, бот и отчёт отвечают одинаково.
- Процессы в `docker-compose.yml`: `collector` (прогоны по расписанию + посты + отчёт + оповещения),
  `bot` (long polling, модерация, отправка, голос), `api` (HTTP). База общая — именованный том `kiravto-data`
  (SQLite в WAL ненадёжен на bind-mount Docker Desktop); модель распознавания речи — том `kiravto-models`.

## Запуск

```bash
python -m kiravto secrets      # скрытый ввод токенов в .env (агент их не видит)
docker compose up --build      # сборщик + бот + API (порт 8080)
docker compose run --rm tests  # тесты в контейнере
```

Без docker (Python 3.11+):
```bash
python -m venv .venv && .venv/bin/pip install -r requirements.txt && .venv/bin/playwright install chromium
python -m kiravto run-once     # один прогон, печатает метрики
python -m kiravto serve        # сборщик + бот + API в одном процессе
python -m pytest -q            # тесты, без сети
```

Windows без Docker: `powershell -File scripts\run_local.ps1` (сборщик + бот + API, лог `data\serve.log`);
автозапуск при входе в систему — `scripts\install_autostart.ps1` (задача планировщика «Kiravto»).

Прочие команды: `status` (прогоны и очередь), `tg-check` (бот отвечает? ID чатов, права бота в каналах),
`sample 20` (выборка для сверки), `report`, `dump-fixtures`, `mcp`, `market --groups 40` (дозаполнить «ниже рынка»
сразу), `rolf-sync` (второй источник), `sheets-export` (Google Таблица), `ask что подешевело за неделю`
(тот же ответ, что на голосовое).

## Откуда данные и почему так

Страница салона сама получает склад JSON-запросом **`POST /-/ajax/desktop-search/listing/`**
(параметры `dealer_id=20866489`, `section=new|used`, `page`, `page_size` — максимум 50), а карточку —
**`POST /-/ajax/desktop-search/getOfferCard/`** (`offer_id=<id>-<hash>`). Нашли это, записав сетевые
запросы страницы в Playwright MCP при переходе на 2-ю страницу (журнал, разведка). Берём те же JSON:
в них все поля в структурированном виде (цена, скидки по условиям, VIN, ПТС, фото в исходном размере,
даты), а вёрстка показывает их урезанно и меняется чаще.

- **Скрытые фильтрами машины.** По умолчанию выдача добавляет `has_image=true`,
  `damage_group=NOT_BEATEN`, `customs_state_group=CLEARED`. Мы явно ставим `has_image=false`,
  `damage_group=ANY`, `customs_state_group=DOESNT_MATTER`.
  20.10 без фильтров было 453 против 428 на сайте. Сначала я решил, что разница — машины без фото, но
  **это не подтвердилось**. 21.10 в 01:41 прогон собрал 453, и у 26 из них карточка уже `REMOVED`
  (сайт пишет «Этот автомобиль уже продан. Объявление доступно только по прямой ссылке»). В 01:55 обе
  выдачи — с фильтрами и без — дали ровно 427. Вывод: разница была в проданных машинах, которые индекс
  выдачи ещё не убрал, а не в спрятанных. Снятие фильтров оставлено: оно ничего не ломает и подстрахует,
  если появится машина без фото или нерастаможенная.
- **Почему браузер, а не httpx.** Обычный HTTP-клиент с новой сессией получает `NEED_AUTH`
  («Войдите, чтобы пользоваться сервисом дальше») или редирект на `auth.auto.ru`. Обычный Chromium со своей
  новой сессией получает данные как посетитель. Чужих cookie/аккаунтов и сервисов капчи нет.
  Страница салона открывается один раз за прогон, дальше — `fetch` из её контекста.
- **Выдача отстаёт — цену берём из карточки.** Сверка 20 случайных машин с сайтом (21.10) показала:
  у 10 из 20 цена и скидки в выдаче не такие, как на сайте. В JSON выдачи `update_date` этих машин —
  11.10, в карточке — 21.10, а цена карточки совпадает с сайтом. Ещё выдача держит уже проданные машины
  (карточка `REMOVED`). Поэтому выдача — только **индекс ID** и подсказка «что-то поменялось»; цена,
  скидки, наличие, пробег, описание и фото обновляются **только из карточки**. Раз изменение цены
  в выдаче можно вовсе не увидеть, карточки ещё и обходятся по кругу (`REFRESH_CARDS_PER_RUN`,
  по умолчанию 60 самых давно проверенных за прогон): на складе ~430 машин, при прогоне раз в 45 минут
  каждая перепроверяется примерно раз в 5–6 часов. Это компромисс между точностью и бережностью;
  снижение цены сервис видит с задержкой до нескольких часов.
- **Бережность.** Пауза 2–4.5 с между запросами, повтор с нарастающей задержкой (5→10→20 с).
  Карточка запрашивается только для новых машин и тех, у кого в выдаче что-то поменялось
  (подпись: цена, скидка, пробег, наличие, комплектация, число фото, дата поднятия), не больше
  `MAX_CARDS_PER_RUN` за прогон — остальное доделает следующий. Число запросов пишется в каждый прогон.
- **Поля.** Цена со всеми скидками = `price − discount_options.max_discount` (так считает сам сайт:
  «2 649 000 ₽ → 2 419 000 ₽ со скидками» у Hongqi HS5 #1160027054). Условия: трейд-ин/кредит/страховка.
  VIN Авто.ру отдаёт только частично (`LFB**************`) — храним видимую часть.
  Цвет приходит кодом (`FFD600`), подпись берём из палитры сайта. Объём двигателя — как его пишет сайт
  (`tech_param.human_name`: 3346 см³ → «3.4»), точные кубики хранятся отдельно (`engine_cc`). Фото — алиас `orig` на CDN (исходное
  разрешение, порядок как на сайте). Владельцы/ПТС/растаможка — для машин с пробегом.

## Как устроены «снято», «перевыставлено», «продано»

- **Прогон полный**, только если: не было блокировки, собрано ≥ 90% прошлого склада **и** ≥ 90% от того,
  сколько заявил сам источник. Иначе прогон `incomplete`: цены по увиденным машинам обновляются,
  но **никто не снимается**. Одна блокировка не «продаст» салон.
- **Сдвиг выдачи.** Пока листаем, выдача сдвигается. Если по сортировке по умолчанию собрали меньше,
  чем заявлено, делаем второй проход с сортировкой по дате (`cr_date-desc`) и объединяем по ID.
- **Снято.** Машина была активна, а в полном прогоне её нет → запрашиваем её карточку.
  `OFFER_NOT_FOUND` или статус не `ACTIVE` → `removed`. Карточка живая → событие `still_active`
  (просто не попала в выдачу), ничего не снимаем.
- **Вернулось.** Тот же ID снова в выдаче → `returned`, статус снова `active`.
- **Перевыставлено** (новый ID той же машины), по порядку:
  1. полный VIN совпал (Авто.ру его почти всегда прячет, но если откроет — сработает);
  2. та же марка/модель/год/раздел, совместимые видимые части VIN **и** хеш первого фото (dHash по
     пикселям, расстояние Хэмминга ≤ 6). Хеш по содержимому, а не по ссылке — при перезаливке ссылка новая.
     Фото, одинаковое у нескольких машин (каталожное), не учитывается;
  3. для машин с пробегом — совпали поколение, комплектация, мощность, КПП, привод, кузов, цвет,
     а пробег не уменьшился и вырос не больше чем на 3% (мин. 500 км).
  Новый ID должен появиться **позже** старого: увиденные в одном прогоне — две разные машины.
  **Новые машины — только по полному VIN.** Машины одной партии совпадают по всем характеристикам,
  фото у них каталожные, от VIN видно 3 символа. Первый полный живой прогон дал по п.2–3 восемь ложных
  «перевыставлений» RAV4/Prado/Corolla Cross — поэтому для новых эти признаки отключены (ограничение, не баг).
- **Вероятно продано.** Снято и не вернулось (ни тем же ID, ни перевыставлением) за `SOLD_AFTER_DAYS` дней
  (по умолчанию 7).
- **Дубли.** Два активных объявления одной машины: полный VIN или хеш фото + те же марка/модель/год
  (только с пробегом). Помечаем `duplicate_of`, не удаляем.
- **Аномалии** помечаются, а не выбрасываются: цена ≤ 1000 ₽, пробег 0 у машины с пробегом, год из
  будущего, цена в 10 раз ниже медианы по модели, пробег > 1,5 млн км.

## Подключение MCP к агенту

В репозитории `.mcp.json` — Claude Code подхватит сервер `kiravto` сам при запуске в корне проекта.
Команда в нём — `python`, поэтому `claude` запускайте из окружения, где стоят зависимости:
`source .venv/bin/activate` (Windows: `.venv\Scripts\activate`), затем `claude`. Проверить: `/mcp` в Claude Code.
Вручную: `claude mcp add kiravto -- python -m kiravto.mcp_server` (из корня репозитория; база —
`DB_PATH` или `data/kiravto.db`). Другие клиенты — stdio-команда `python -m kiravto.mcp_server`.

Если сервис работает в `docker compose`, база лежит в томе контейнера, а не в `data/`. Для неё в `.mcp.json`
есть второй сервер `kiravto-docker`: тот же MCP, запущенный внутри контейнера
(`docker exec -i kiravto-api-1 python -m kiravto.mcp_server`). Вручную:
`claude mcp add kiravto-docker -- docker exec -i kiravto-api-1 python -m kiravto.mcp_server`.

Инструменты: `search_offers`, `get_offer`, `get_offer_history`, `get_price_drops`, `get_stock_summary`,
`get_runs_status`, `get_below_market`, `get_second_source` (чтение) и `propose_post` — ставит пост в модерацию
и возвращает предупреждение. Инструмента «опубликовать» нет.

MCP на VPS (там своя база): `ssh vps docker exec -i kiravto-api-1 python -m kiravto.mcp_server` — та же stdio-команда
через ssh, например `claude mcp add kiravto-vps -- ssh vps docker exec -i kiravto-api-1 python -m kiravto.mcp_server`.

## Telegram

Каждый пост сначала приходит в админ-чат с кнопками «Опубликовать»/«Отклонить». Переход статусов
атомарный (`UPDATE … WHERE status='moderation'`) — второе нажатие ничего не публикует. По умолчанию
публикуется в **тестовый** канал. Боевой включается только человеком: строкой `TG_PUBLISH_TARGET` в `.env`
(значение `prod`). Ни бот, ни команды, ни агент этого не умеют; хук `guard.py` запрещает агенту такую правку.
Посты: «Новые за день» (раз в день после `DAILY_POST_TIME`, альбом до 10 фото + карточки) и
«Цена снижена» (снижение ≥ `DROP_MIN_PCT`%, одна машина — не чаще раза в сутки). Ключи дедупликации
хранятся в базе — после перезапуска старое не публикуется заново.

## HTML-отчёт по складу

После каждого прогона сервис пересобирает `data/report.html`. В нём:
- машин в продаже сейчас и неделю назад; если база моложе 7 дней, отчёт честно пишет, что посчитать нельзя;
- средний срок экспозиции до снятия;
- медианная цена по моделям;
- сильнейшие снижения цены за неделю;
- доля аномалий и неполных прогонов;
- факты LLM (оставлено и выброшено);
- последние прогоны с метриками.

Открыть отчёт можно файлом, через API `GET /report` (с токеном) или в Docker:
`docker compose cp collector:/app/data/report.html .`.

## Задания со звёздочкой

### 1. «Ниже рынка» — `market.py`
Для каждой машины ищем такие же у **других продавцов Авто.ру** тем же JSON-эндпоинтом выдачи, но без
`dealer_id`: `catalog_filter=[{mark, model, generation}]`, `year_from/to` = год ±1, `km_age_from/to` = пробег ±20 %
(у новых пробег не сравниваем), Москва и 200 км (`geo_id=[213]`, `geo_radius=200`). Машины самого салона
из выборки выкидываются. `market_pct` = (цена − медиана) / медиана × 100; меньше `MARKET_MIN_COMPS` (5) похожих —
оценки нет, а не процент по двум машинам.
- **Бережно:** один поиск на группу «раздел + марка + модель + поколение» с диапазоном годов и пробегов сразу
  для всех её машин (≈160 групп на складе), не больше `MARKET_GROUPS_PER_RUN` (12) групп за прогон, выборка живёт
  `MARKET_TTL_HOURS` (48 ч). Весь склад обходится примерно за 10 часов; `python -m kiravto market` — сразу.
- **Ловушки источника, найденные вживую:** (1) новые машины Авто.ру отдаёт свёрнутыми в группы — одна карточка
  «133 предложения» с одной ценой; поиск новых идёт с `output_type=list`, а карточка-группа в медиану не берётся;
  (2) фильтр, которого нет в эхе `search_parameters`, — это смена формата, поиск падает громко (иначе «рынок»
  молча посчитался бы по всей стране, как когда-то с `dealer_code`); (3) между страницами выдача сдвигается —
  похожие дедуплицируются по ID.
- **В сообщество — только ниже рынка:** `MARKET_BELOW_PCT=N` в `.env` — в «Цена снижена» и «Новые за день»
  попадают только машины дешевле медианы на N % и больше (без оценки — не попадают). По умолчанию фильтр выключен,
  а в каждом посте есть строка «📊 ниже рынка на 7% (медиана … по 23 похожим на Авто.ру)».
- Где видно: `GET /market`, MCP `get_below_market`, раздел «Ниже рынка» в HTML-отчёте, поле `market_pct` в машинах.

### 2. Второй источник — сайт салона, `second_source.py`
Сайт rolf.ru (Nuxt) берёт склад из JSON **`GET apiweb.rolf.ru/api/v2/vehicles/total`** с фильтром
`dealer_id[0]=38` («РОЛЬФ Ясенево»), `vehicle_type=new|used`, `per_page` до 60. Нашли в `window.__NUXT__`
страницы `/cars/used/?dealer_id[0]=38` (Playwright MCP). API отвечает обычному HTTP-клиенту без входа; раз
в `ROLF_INTERVAL_HOURS` (6 ч), ~14 запросов.
Главное: **сайт салона отдаёт VIN целиком**, Авто.ру — только 3 символа. Склейка в одну запись (`offer_sources`):
- с пробегом — видимая часть VIN + марка + модель + год + пробег (±1 %);
- новые — видимая часть VIN + марка + модель + год + цвет + цена (±3 %), и только если кандидат ровно один и на
  него не претендует другое объявление (машины одной партии неразличимы — лучше не склеить, чем склеить чужую).
Где видно: `GET /offers/{id}` → `sources` (полный VIN, цена на сайте, ссылка, признак склейки),
`GET /second-source`, MCP `get_second_source`, раздел в HTML-отчёте, колонка «VIN (сайт салона)» в таблице.

### 3. Голосом — `voice.py`
Голосовое в админ-чате → `getFile` → распознавание **локально** (faster-whisper `small`, без ключей и без отправки
голоса третьим лицам; модель скачивается один раз в том `kiravto-models`) → вопрос сводится к инструменту
**MCP-сервера** (`get_price_drops`, `get_below_market`, `get_stock_summary`, `get_runs_status`, `search_offers`) →
ответ в чат. Маршрутизация — правилами («подешевело за неделю больше чем на 5 %» → `get_price_drops(days=7,
min_pct=5)`); если правила не узнали вопрос и LLM настроена, инструмент выбирает LLM, но только из белого списка
чтения — `propose_post` голосом недоступен. Цифры в ответе собирает код из ответа инструмента, не LLM.
Текстом — `/ask вопрос` в админ-чате или `python -m kiravto ask …`. `STT_MODEL=off` выключает голос.

### 4. Google Таблица — `gsheets.py`
Листы «Склад» (с оценкой рынка и полным VIN с сайта салона), «Снижения за неделю», «Прогоны», «О выгрузке» —
перезаписываются целиком раз в `GSHEET_INTERVAL_HOURS` (3 ч) или командой `sheets-export`. API сервисного
аккаунта без библиотек Google: JWT (RS256) подписывается `cryptography`, запросы — httpx.
**Настройка (человек):** `powershell -ExecutionPolicy Bypass -File scripts\setup_gsheets.ps1` — включает Sheets API,
создаёт сервисный аккаунт, кладёт ключ в `secrets\kiravto.sa.json` (в `.gitignore`; хук `guard.py` не даёт агенту
его читать), спрашивает ссылку на таблицу и пишет `GSHEET_ID` в `.env`. Таблицу создаёте вы и даёте сервисному
аккаунту доступ «Редактор»: своего места на Диске у сервисного аккаунта нет. В Docker ключ монтируется только
для чтения (`./secrets:/app/secrets:ro`).

### 5. Сервер — `deploy/`
VPS (Ubuntu 24.04, Docker из пакетов Ubuntu), код в `/opt/kiravto/app` (git clone публичного репозитория).
`deploy/docker-compose.vps.yml` поверх основного: **сборщик + API (+ MCP через `docker exec`)**, без бота — на одном
токене может работать только один бот, он остаётся на основной машине; API слушает только `127.0.0.1:8080`
(порт наружу не открыт, доступ `ssh -L 8080:127.0.0.1:8080 vps`). `.env` на сервере создаёт сам скрипт — только
`API_TOKEN`, сгенерированный там же.
- **Выкатка:** `/opt/kiravto/app/deploy/deploy_vps.sh [ref]` — git fetch, прошлые образы помечаются
  `kiravto-*:rollback`, сборка, тесты в контейнере, `up -d`, проверка `/health`.
- **Журнал действий на сервере:** `/opt/kiravto/DEPLOY_LOG.md` — каждый шаг с временем и коммитом.
- **Откат:** `/opt/kiravto/app/deploy/rollback_vps.sh` — прошлые образы и прошлый коммит без пересборки. База
  не трогается: схема только дополняется (`ADD COLUMN`, `CREATE … IF NOT EXISTS`), старая версия новых колонок
  просто не читает.

## Что не сделано и почему

- **Перевыставление у новых машин практически не определяется.** Авто.ру скрывает VIN (видно 3 символа),
  у машин одной партии одинаковые характеристики и каталожные фото. Правило по характеристикам дало ложные
  совпадения, поэтому для новых машин оставлен только полный VIN. Полный VIN теперь есть у машин, склеенных
  с сайтом салона, но в перевыставление он пока не подключён.
- **Справочника моделей нет**, только марок. Внутри Авто.ру модель сравнивается по коду; со вторым источником
  склейка сравнивает названия без пробелов и знаков («RAV4» = «RAV 4») — для rolf.ru этого хватило.
- **Новые машины на сайте салона и на Авто.ру — в основном разные.** У «РОЛЬФ Ясенево» на rolf.ru среди новых
  в основном Voyah, Changan, Jetour, а на Авто.ру — Toyota и Lexus; у совпадающих моделей цены часто другие.
  Поэтому склеено мало новых (19 из 158) — это не ошибка склейки, а разный склад.
- **Бережность против точности.** Выдача отстаёт на дни, поэтому каждый прогон перечитывает по кругу
  60 карточек (`REFRESH_CARDS_PER_RUN`). Это больше, чем «только новые и изменившиеся» из ТЗ, но иначе
  снижение цены можно не увидеть вовсе.
- **«Снято» по карточке `REMOVED` фиксируется и в неполном прогоне:** это подтверждённый статус, а не пропажа
  из выдачи. Правило «< 90% — никого не снимаем» относится к машинам, которых просто нет в выдаче.
- **Голосовые в группе доходят до бота, только если он администратор** группы или у него выключен режим
  приватности (@BotFather → `/setprivacy`). Иначе Telegram отдаёт боту в группе лишь `/команды`; `tg-check` это
  показывает. Текстом вопрос задаётся всегда: `/ask …`.
