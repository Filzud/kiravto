# Разведка источника данных

Цель — брать данные из того, чем пользуется сам сайт, а не из вёрстки. Вёрстка меняется чаще и врёт (обрезанные списки, ленивые фото).

## Шаги
1. **Открой страницу в браузере** (Playwright MCP: `browser_navigate`). Посмотри, что видит человек: счётчики («428 предложений»), пагинацию, фильтры по умолчанию.
2. **Запиши сетевые запросы** (`browser_network_requests`, без статики) при загрузке и при действии (следующая страница, фильтр). Ищи `/api/`, `/ajax/`, `graphql`, JSON-ответы.
3. **Проверь встроенное состояние**: `<script type="application/json">`, `window.__INITIAL_STATE__`, `__NEXT_DATA__`. Если данных там нет — они приходят XHR.
4. **Повтори запрос из контекста страницы** (`browser_evaluate` + `fetch`) — с теми же заголовками (CSRF из cookie). Меняй по одному параметру: ID продавца, `page`, `page_size` (узнай максимум), сортировку.
5. **Найди скрытое фильтрами**: сравни `total_count` с фильтрами по умолчанию и без них (фото, состояние, растаможка, наличие). Разница = то, что сайт прячет.
6. **Проверь простой HTTP-клиент** (`curl`/`httpx` с новой сессией). Если он получает «войдите»/капчу, а браузер нет — собирай браузером с собственной сессией. Чужие cookie, аккаунты и сервисы капчи — нельзя.
7. **Сохрани фикстуры**: по одному реальному ответу каждого вида (список, карточка, «не найдено», ошибка) в `tests/fixtures/`. Урежь большие списки, но не меняй структуру.
8. **Запиши выводы** в README («Откуда данные») и в отчёт: эндпоинты, параметры, лимиты, что прячется, как выглядит блокировка.

## Чего не делать
- Не долби источник: пауза 2–5 с между запросами, не больше пары десятков запросов на разведку.
- Не угадывай поля по названию — открой карточку на сайте и сверь значение глазами.
- Не обходи защиту. Упёрся — опиши, что видел, и остановись.

## Результат
Короткая таблица: эндпоинт → метод → параметры → что отдаёт → лимиты → признаки блокировки. Плюс сохранённые фикстуры.
