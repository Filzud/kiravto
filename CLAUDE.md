# Киравто: склад автосалона → Telegram

Сервис раз в 30–60 минут собирает склад салона РОЛЬФ Ясенево с Авто.ру, хранит историю цен и статусов,
готовит посты в Telegram (публикует только человек кнопкой), отдаёт данные через HTTP API и MCP-сервер.
Код — `kiravto/`, тесты — `tests/`, архитектура и «как устроено» — `README.md`.

## Что значит «готово»
Задача готова, только когда выполнено всё:
1. Тесты зелёные: `.venv/Scripts/python -m pytest` (Linux: `.venv/bin/python`). Stop-хук не даст закончить с красными.
2. Новое поведение покрыто тестом на сохранённых ответах (`tests/fixtures/`), без сети.
3. Если менялся сбор или разбор — был живой прогон `python -m kiravto run-once`, и в отчёте его цифры:
   собрано / заявлено источником, запросов, ошибок, новых, изменений, снято.
4. Если менялись поля объявления — сверка с сайтом (субагент `verifier` или руками через Playwright MCP),
   расхождения разобраны.
5. Отчёт написан в формате ниже, неподтверждённое помечено как неподтверждённое.

«Синтаксис прошёл», «импорт работает», «должно работать» — это не проверка.

## Как проверять
- Юнит/интеграция: `pytest` в 1 поток (без `-n`), сеть не нужна.
- Живой прогон: `python -m kiravto run-once` → смотри строку итога и `data/report.html`.
- Сверка: `python -m kiravto sample 20` даёт 20 случайных машин из базы → субагент `verifier` сравнивает с сайтом.
- MCP: `pytest tests/test_mcp.py` (настоящий MCP-клиент по stdio).
- Сомневаешься в формате источника — скилл `source-recon`, не угадывай поля.
- Рынок, сайт салона, таблица: `python -m kiravto market --groups N`, `rolf-sync`, `sheets-export`; их запросы
  и итог — в таблице `side_runs`. Фильтр поиска, которого нет в эхе `search_parameters`, — смена формата.
- Голос без Telegram: `python -m kiravto ask <вопрос>` — тот же путь «вопрос → инструмент MCP → ответ».

## Чего агенту нельзя
- Читать `.env`, выводить окружение, писать токены в файлы, команды и чат. Секреты вводит человек:
  `python -m kiravto secrets` (скрытый ввод). Хук `guard.py` это блокирует — не обходи его.
  То же для ключа Google: `secrets/`, `*.sa.json` создаёт человек скриптом `scripts/setup_gsheets.ps1`.
- Включать боевой канал. По умолчанию всё идёт в тестовый; боевой включает только человек правкой `.env`.
- Публиковать что-либо без кнопки человека. Нет и не будет инструмента «опубликовать напрямую».
- Обходить капчу сервисами, брать чужие аккаунты и cookie, поднимать частоту запросов. Упёрлись в защиту —
  прогон помечается неполным, пишем в отчёт, что сделали бы дальше.
- Считать машины снятыми по неполному прогону. Править фикстуры, чтобы «позеленить» тест.
- Запускать своих субагентов из субагента; в параллельной работе — править файлы чужой ветки.
- Убивать процессы по имени (`taskkill /IM python.exe`, `pkill python`) — на машине живут чужие процессы.
  Останавливай только свой процесс по PID.

## Параллельная работа
Независимые части (бот, API+отчёт, MCP+LLM) — каждая в своём `git worktree` и ветке. Общие файлы
(`db.py`, `queries.py`, `posts.py`, `config.py`) правит только основной агент. Результат субагента
перепроверяется: чтение диффа + тесты + живой прогон, в отчёте — что и как перепроверено.

## Формат отчёта (итог и промежуточные)
```
### Жду от вас
- что нужно от человека (токен, решение, доступ) — или «ничего»
### Сделано
- что, с цифрами (сколько собрано/тестов/запросов) и КАК проверено
### Нашёл
- что узнали про источник, баги, риски; неподтверждённое помечено «не проверено»
```
